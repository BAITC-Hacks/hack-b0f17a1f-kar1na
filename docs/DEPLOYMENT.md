# Деплой: Render + Vercel

Render запускает Python API и отдаёт 3D-модель, Vercel — собранный сайт. Локальный запуск через `make` остаётся прежним.

## 1. Render: backend

Отправьте изменения в GitHub. В Render создайте Blueprint из репозитория, используя корневой `render.yaml`, либо Web Service с такими настройками:

| Поле | Значение |
| --- | --- |
| Runtime | Python 3 |
| Root Directory | оставить пустым (корень репозитория) |
| Build Command | `pip install -r requirements.txt` |
| Start Command | `python -m uvicorn src.api.main:app --host 0.0.0.0 --port $PORT --workers 1` |
| Health Check Path | `/api/health` |
| Instance Type | Free для первого демонстрационного запуска |

Файл `.python-version` выбирает Python 3.11. Модели и данные берутся из репозитория; обучение при деплое не требуется. Не выбирайте Docker автоматически: для этой схемы используется Python runtime.

Переменные окружения Render:

| Переменная | Значение |
| --- | --- |
| `FORECAST_MODE` | `replay` |
| `WEATHER_ALLOW_FALLBACK` | `false` |
| `WEATHER_OFFLINE` | `false` (разрешает Live) |
| `AGENT_MONITOR_ENABLED` | `false` (без фонового опроса для демо) |
| `CORS_ORIGINS` | точный адрес сайта Vercel, например `https://your-site.vercel.app`, без завершающего `/` |

Если адрес Vercel ещё неизвестен, временно оставьте `CORS_ORIGINS=http://localhost:5173`, затем замените его после создания сайта. Несколько разрешённых адресов перечисляются через запятую без пробелов. Preview-домены Vercel отличаются от постоянного production-домена: для них тоже нужно явно разрешить origin.

После деплоя откройте `https://YOUR-SERVICE.onrender.com/api/health`: ожидаются `status: "ok"` и `ready: true`. Корневой адрес Render в этой схеме может возвращать 404 — сайт размещён на Vercel.

## 2. Vercel: frontend

Импортируйте тот же репозиторий. **Root Directory оставьте корнем репозитория (`./`), не `web`**: frontend импортирует контроллер из `3d/web`. Корневой `vercel.json` задаёт:

| Поле | Значение |
| --- | --- |
| Framework Preset | Vite |
| Install Command | `npm ci --prefix web` |
| Build Command | `npm run build --prefix web` |
| Output Directory | `web/dist` |

Добавьте переменную окружения для Production (и Preview, если нужен):

```text
VITE_API_BASE_URL=https://YOUR-SERVICE.onrender.com
```

Укажите реальный адрес Render **без `/api`**. Переменная встраивается в сайт при сборке: после её изменения нужен новый деплой. API-запросы, экспорт CSV, контекстный агент и GLB используют этот адрес.

Нажмите Deploy. Скопируйте постоянный адрес сайта и сохраните его в `CORS_ORIGINS` на Render. Дождитесь перезапуска backend, затем откройте сайт Vercel.

## 3. Проверка

1. Откройте `/#overview`: загрузились обе турбины, данные и 3D-модель.
2. Переключите турбину и горизонт 24/48 часов в Replay.
3. В Analytics проверьте графики и архивную историю.
4. Скачайте CSV и проверьте, что это прогноз, а не HTML-страница ошибки.
5. При необходимости проверьте Live: он требует доступности внешнего погодного API.

Численные прогнозы не требуют OpenAI. Для языковых ответов `OPENAI_API_KEY` задаётся **только на Render**, никогда в переменных `VITE_*`: они видны посетителям. У API пока нет авторизации и ограничения частоты запросов, поэтому подключение ключа к публичному демо делает платные вызовы доступными посетителям; первый деплой можно проверить без ключа.

Free-сервис Render засыпает после простоя, поэтому первый запрос может занять время. Файлы прогнозов и журналов на его локальном диске не являются постоянным хранилищем. Если процесс завершается из-за нехватки памяти, проверьте логи и потребление ресурсов перед выбором другого тарифа.

## Если деплой не работает

- **Ошибка установки Python-пакетов:** проверьте Python 3.11 и корневой каталог Render.
- **Сайт открылся, но API/3D недоступны:** проверьте `VITE_API_BASE_URL`, `/api/health` и точное совпадение `CORS_ORIGINS` с доменом страницы.
- **После смены адреса API сайт обращается к старому:** выполните Redeploy на Vercel.
- **Репозиторий не виден:** для приватного репозитория организации требуется доступ соответствующей GitHub-интеграции. Его может выдать администратор организации; не делайте репозиторий публичным ради деплоя.
- **GitHub Actions не запускается из-за billing:** проверьте логи самого хостинга. Render и Vercel имеют собственные сборки; ошибка GitHub Actions сама по себе не является ошибкой сборки на хостинге.

Документация: [Render Web Services](https://render.com/docs/web-services), [Python на Render](https://render.com/docs/python-version), [Vite на Vercel](https://vercel.com/docs/frameworks/frontend/vite).
